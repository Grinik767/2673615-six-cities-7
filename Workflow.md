# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

Перед первым запуском создайте в корне проекта `.env` на основе `.env-example`:

```powershell
Copy-Item .env-example .env
```

Для Linux/macOS используйте `cp .env-example .env`. Заполните все три обязательные переменные:

| Переменная | Значение |
| --- | --- |
| `PORT` | Номер порта приложения |
| `DB_HOST` | Валидный IPv4- или IPv6-адрес сервера базы данных |
| `SALT` | Непустая строка со случайным набором символов для хеширования паролей |

```bash
npm start
```

Команда собирает проект и запускает `main.rest.ts`.

Для разработки с форматированными логами используйте отдельный сценарий:

```bash
npm run start:dev
```

Сценарий собирает проект и передаёт логи в `pino-pretty`.

#### Запустить JSON-server с заготовками данных

```bash
npm run mock:server
```

Запускает тестовый REST API на порту `3123`. Заготовки из `mocks/mock-server-data.json` доступны по адресу `http://localhost:3123/api`. Оставьте сервер работающим и выполняйте команды CLI в другом терминале.

#### Сгенерировать тестовые предложения

```bash
npm run cli -- --generate 100 ./mocks/generated-offers.tsv http://localhost:3123/api
```

Команда `--generate <n> <filepath> <url>` получает заготовки с JSON-сервиса и записывает указанное количество предложений в TSV-файл. Количество должно быть положительным целым числом. Каждое предложение занимает одну строку с 17 полями; элементы списков разделяются `;`. Дата публикации выбирается за последнюю неделю, координаты соответствуют выбранному городу. Существующий файл по указанному пути перезаписывается.

#### Импортировать предложения

```bash
npm run cli -- --import ./mocks/generated-offers.tsv
```

Команда выводит предложения в консоль и сообщает итоговое количество. Чтение и запись выполняются потоками: файл целиком в память не загружается, поэтому можно обрабатывать TSV размером больше 2 GB. Пустые строки пропускаются, поддерживаются UTF-8 BOM, CRLF и последняя строка без перевода строки. Ошибка в данных содержит номер строки.

#### Проверить команды на большом файле

После запуска JSON-server скомпилируйте проект и выполните:

```bash
npm run compile
node --max-old-space-size=64 ./dist/main.cli.js --generate 5000000 ./mocks/large-offers.tsv http://localhost:3123/api
node --max-old-space-size=64 ./dist/main.cli.js --import ./mocks/large-offers.tsv
```

Такой набор занимает больше 2 GB. Импорт выводит каждое предложение, поэтому для проверки большого файла можно перенаправить вывод: в PowerShell добавьте `> $null`, в cmd — `> NUL`, в Linux/macOS — `> /dev/null`.

Сгенерированные TSV исключены из Git через `.gitignore`. Учебный файл `mocks/offers.tsv` из первого задания сохранён в репозитории.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
